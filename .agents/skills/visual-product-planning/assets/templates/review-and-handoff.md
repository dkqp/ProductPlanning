# 화면 검토와 구현 전환

## 대상과 근거

- 과업과 범위:
- 기획서·화면·가이드 버전:
- 검토 방식과 참여자:
- 수행한 시나리오와 관찰 근거:
- 화면 품질 평가·미해결 문제 목록:
- 사용자 테스트 계획·실제 세션·결과 분류:

기획자 검토, 실제 사용자 관찰, 에이전트 자체 점검을 구분한다.

## 전환 판단

| 기준 | 확인 / 미확인 / 해당 없음 | 근거 또는 처리 방안 |
|---|---|---|
| 핵심 과업을 처음부터 끝까지 수행할 수 있다 | | |
| 화면·기획·가이드의 용어와 동작이 일치한다 | | |
| 중요한 규칙과 예외의 결과가 정해져 있다 | | |
| 실제 사용자 검증과 남은 가설이 드러나 있다 | | |
| 기술 위험의 확인 결과 또는 계획이 있다 | | |
| 구현 범위와 전환 의사가 확인됐다 | | |

미확인은 통과가 아니다. 핵심 과업의 치명적인 문제는 해결·범위 변경으로 처리하고 중요한 미확인에는 담당·확인 계획을 적는다. 사용자 테스트가 없으면 그 사실과 전환 판단의 한계를 기록한다. 위험 수용은 결정권자·이유·범위를 남긴다.

## 결정

시안 수정 / 추가 사용자 검증 / 기술 실험 / 정한 범위의 구현 중 다음 행동과 이유를 적는다. 승인 범위와 미해결 사항을 구분한다.

준비됨 / 조건부 / 재검토 중 판단, 근거 버전, 남은 문제의 조치와 재검증 조건을 적는다. 이 분류는 프로젝트 운영용이며 외부 인증이나 총점이 아니다.

# 화면 품질 평가

## 평가 대상을 고정한다

사용자 역할·과업·기기·화면 버전·상태·시안의 구현 범위를 적고 현재 화면을 직접 본다. 원본과 미리보기 또는 실행 화면의 증거를 연결한다. 과거 평가가 있으면 버전이 같은지 확인한다. 평가 결과는 [양식](../assets/templates/screen-quality-review.md)에 남긴다.

정적 시안에서는 구성과 표현을, 클릭 시안에서는 연결된 상호작용을 확인한다. 실제 서비스의 성능·저장·권한·보조기술 동작은 해당 환경에서 확인한다. 보이지 않는 속성을 상상해서 통과시키지 않는다.

## 과업을 따라 검토한다

아래는 [Nielsen의 휴리스틱](https://www.nngroup.com/articles/ten-usability-heuristics/)을 기획 단계에 적용한 질문이다. 모든 항목에 그림을 더 만드는 절차가 아니라 해당 과업에서 중요한 문제를 찾는 기준이다.

| 관점 | 확인할 질문 |
|---|---|
| 상태 | 현재·진행·완료를 구분할 수 있는가? |
| 사용자 언어 | 표현·단위·순서가 사용자의 업무에 맞는가? |
| 통제 | 취소·뒤로·수정·재시도가 가능한가? |
| 일관성 | 같은 행동에 같은 이름·결과를 쓰는가? |
| 오류 예방 | 위험한 실수와 조건 누락을 막는가? |
| 인지 부담 | 필요한 정보가 보이며 기억에 의존하지 않는가? |
| 효율 | 초보자와 반복 사용자의 과업을 지원하는가? |
| 정보 우선순위 | 주요 과업·정보·행동이 두드러지는가? |
| 복구 | 오류 원인·보존된 내용·다음 행동이 보이는가? |
| 도움 | 필요한 위치에서 구체적인 안내를 얻는가? |

정상 흐름에 더해 실패·대기·빈 상태·권한·긴 내용 중 과업에 영향을 주는 상태를 고른다. 한국어 줄바꿈·긴 제목·실제 데이터 밀도로 읽어 본다. 모든 제품에 특정 색·배치·화면 수를 강요하지 않는다.

## 웹 접근성 확인

기준은 [WCAG 2.2 본문](https://www.w3.org/TR/WCAG22/), 아래 설명 링크는 이해를 돕는 해설이다. 프로젝트가 목표하는 준수 범위와 관련 항목을 정한다. 이 표만으로 전체 A/AA 준수를 선언하지 않는다.

| 항목 | 적용 조건과 확인 방법 |
|---|---|
| 텍스트 대비 1.4.3 AA | 일반 텍스트 4.5:1, 큰 텍스트 3:1. 큰 텍스트는 18pt 또는 굵은 14pt 이상이다. 비활성 컴포넌트·장식·로고 등의 예외를 구분한다. [해설](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) |
| 비텍스트 대비 1.4.11 AA | 식별에 필요한 컨트롤·상태·의미 있는 그래픽은 인접 색과 3:1. 비활성 등 예외가 있다. 원본 색을 계산하고 실제 상태를 확인한다. [해설](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) |
| 색상 의존 1.4.1 A | 상태·오류를 색만으로 전달하지 않는지 확인한다. |
| 키보드 2.1.1·2.1.2 A | 핵심 행동을 키보드로 수행하고 갇히지 않는지 실행한다. 정적 그림은 미확인이다. |
| 포커스 2.4.7·2.4.11 AA | 포커스가 보이고, 작성한 콘텐츠에 의해 컨트롤이 완전히 가려지지 않는지 실행한다. [해설](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) |
| 타깃 2.5.8 AA | 원칙적으로 24 × 24 CSS px 이상. 간격·동등 기능·문장 내 요소·브라우저 기본·필수 표현의 예외를 확인한다. 그림의 아이콘 크기와 실제 클릭 영역은 다를 수 있다. [해설](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) |
| 확대·리플로 1.4.4·1.4.10 AA | 자막·이미지 텍스트를 제외한 텍스트의 200% 확대에서 정보·기능 손실이 없는지 확인한다. 세로 스크롤 콘텐츠는 폭 320 CSS px 상당에서 손실과 양방향 스크롤을 확인한다. 리플로에는 표·지도 등 필요한 2차원 영역의 예외가 있다. [해설](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) |
| 이름·역할·상태 4.1.2 A·4.1.3 AA | 컨트롤의 이름·역할·값과 해당 상태 알림이 보조기술로 전달되는지 구현에서 확인한다. |
| 입력 오류 3.3.1·3.3.2 A | 오류 식별과 필요한 라벨·안내를 확인한다. 시안의 문구와 구현의 연결을 따로 검토한다. |

계산한 대비는 특정 색 조합의 증거다. 글자 크기·상태·배경·실제 렌더링까지 구분한다. 소수점 표시를 반올림해 경계값을 통과시키지 않는다. 비활성 버튼의 대비 예외가 안내문까지 면제하는 것은 아니다.

## 문제와 근거를 분리한다

판정은 **확인 / 문제 / 미확인 / 해당 없음** 중 하나다. 적용 제외에는 이유를 적는다. 미확인은 통과나 실패에 합산하지 않는다. 아래 심각도는 이 저장소의 운영 기준이며 점수 기반 인증이 아니다.

| 심각도 | 기준 | 다음 행동 |
|---|---|---|
| 치명 | 핵심 과업 차단, 데이터 손실, 중요한 결과의 오해 위험 | 해당 범위의 전환 전 해결 또는 범위 변경 |
| 중요 | 주요 과업에서 혼란·반복 오류·과도한 우회 | 수정안과 재검증 계획 |
| 경미 | 과업을 막지 않는 국소적 불편 | 우선순위와 처리 시점 |

근거는 **실제 사용자 관찰 / 실행 화면 점검 / 정적 화면 점검 / 가설**로 적는다. 한 번 관찰한 일을 모든 사용자의 빈도로 확대하지 않는다. 문제마다 화면·상태·행동·영향·근거·수정안·재검증 방법을 연결한다. 자체 평가로 발견한 위험은 실제 사용자에게 관찰한 사실처럼 쓰지 않는다.

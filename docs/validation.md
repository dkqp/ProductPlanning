# 기획 자료와 스킬 검증 기록

확인일: 2026-11-08. 변경 범위는 기획 문서, 저장소 내 스킬, 양식과 정적 화면 예제다. 실행 서비스·외부 연동·운영 데이터의 변경은 없다.

## 확인한 결과

| 항목 | 방식 | 결과 |
|---|---|---|
| 스킬 형식 | Codex 스킬 생성 도구의 `quick_validate.py` | `Skill is valid!` |
| 내부 문서·이미지 링크 | Markdown 링크의 파일 존재와 문서 제목 앵커 확인 | 전체 내부 링크 확인 |
| 화면 원본 | SVG를 XML로 파싱 | 문법 유효 |
| 실제 미리보기 | SVG를 1800 × 1800 PNG로 렌더링하고 이미지 열람 | 네 화면, 한국어 문구, 버튼과 하단 질문이 잘림 없이 표시됨 |
| 화면·명세·가이드 대응 | TASK-01을 따라 주요 행동과 상태의 명칭 대조 | 초안 검토·출처 보기·확인 표시·완료 저장·재시도·나중에 검토의 대응 확인 |
| 범위와 근거 | 기획 원칙·출처·예제 가정을 문서에서 대조 | 사용자 방향, 적용 제안, 가상 규칙, 미검증 사항 구분 |
| 변경 내용 | `git diff --check`와 변경 파일 검토 | 문서 형식과 변경 범위 확인 |

## 아직 확인하지 않은 것

- 실제 프로젝트에서의 스킬 자동 발견과 인터뷰 품질.
- 실제 대상 사용자의 이해와 과업 수행.
- 예제의 클릭 동작, 실제 저장과 출처 연동, 성능·접근성.
- 외부 프레임워크의 설치, 실제 출력 품질과 비용 비교.

예제에서 아직 그리지 않은 상태와 미정 규칙은 [화면 명세](../examples/report-review/screen-spec.md)에 남겼다. 현재 예제를 실제 제품의 구현 착수 근거로 사용하지 않는다.

## 다음 검증

사용자가 고른 실제 아이디어로 핵심 과업 하나를 실행한다. 인터뷰에서 생긴 오해, 화면을 본 뒤 달라진 결정, 문서와 화면의 불일치, 다음 구현자가 추가로 물어야 했던 중요한 질문을 기록해 스킬을 개선한다.

## 2026-11-14 기준 보강

변경 범위는 스킬·참조·양식·조사 문서와 적용 사례다. 실행 서비스나 운영 데이터 변경은 없다. 원본 화면의 제품 규칙은 새 사용자 결정으로 확정하지 않았다.

- 공개 원문의 실제 절과 샘플 본문을 읽고 [반영 대응표](research/2026-11-14-operational-criteria.md)를 작성했다. 유료 도서 전체를 읽었다고 표시하지 않았다.
- [화면 자체 평가](../examples/report-review/quality-review.md)를 현재 SVG의 재렌더링 이미지·원본 색 계산·명세와 가이드 대조로 수행했다.
- 정적 화면으로 확인하지 못하는 동작·접근성과 실제 사용자 세션은 미검증이다.
- [모의 사례 점검](evaluation-cases.md)은 작성자의 자체 점검으로, 독립 에이전트 평가나 실제 사용자 결과를 대신하지 않는다.
- 스킬 형식 검사 통과, Markdown 25개와 내부 링크·앵커 88개 확인, SVG XML·미리보기 증거 해시·스킬 메타데이터 확인을 완료했다.
- 6개 원본 색 조합을 WCAG 상대 휘도로 계산하고 실제 화면과 적용 조건을 대조했다. 전체 접근성 준수는 미확인이다.
- `git diff --check`와 변경 범위를 검토했다. 예제 화면의 규칙을 임의로 확정하거나 실제 세션 결과를 추가하지 않았다.

반영 대상은 GitHub 저장소의 문서와 스킬이다. 되돌릴 때는 해당 보강 PR의 병합 커밋을 revert한다. 실제 프로젝트 적용과 참여자 테스트가 다음 검증이다.

# 기획 스킬의 모의 사례 점검

확인일: 2026-11-14. 스킬과 참조를 읽은 작성자가 수행한 자체 점검이다. 독립 에이전트의 블라인드 평가나 실제 참여자 테스트는 수행하지 않았다. 아래 요청과 응답 예시는 창작이며 실제 사용자 발언·관찰로 저장하지 않는다.

## 사례와 실제 점검 결과

| 사례 | 점검 입력 | 기대하는 행동 | 수행한 점검과 결과 |
|---|---|---|---|
| E-01 의도와 제안의 구분 | ‘AI가 자료를 알아서 정리해 주면 좋겠어’ | 이유를 먼저 듣고 자동 실행·초안 확인·취소의 차이를 구분. 사용자 결정을 만들지 않음 | 첫 질문을 ‘어떤 상황을 바꾸고 싶으신가요?’로 두고 이후 화면 대안은 제안으로 표시하는 예시를 작성했다. 확정 요구사항과 실제 사용자 근거는 미정으로 유지했다. |
| E-02 정적 화면 평가 | 기존 보고서 검토 v1 | 위치·영향·근거를 갖는 문제 기록. 비활성 대비 예외와 실행 미확인 구분 | [실제 자체 평가](../examples/report-review/quality-review.md)에 Q-01~03과 대비 계산을 기록했다. 작은 체크 표시를 실제 타깃 크기 위반으로 단정하지 않았고 동작 항목은 미확인으로 남겼다. |
| E-03 테스트 계획 | 기존 예제에서 검토 완료·실패 복구를 확인 | 버튼을 지시하지 않는 과업, 평가자용 완료 조건, 도움·중단·결과 분류 | [계획](../examples/report-review/usability-plan.md)에 T-01·02를 작성했다. v1의 상태 부족 때문에 T-01 완료를 실제로 판정할 수 없다고 표시했다. 실제 세션 표나 성공률을 만들지 않았다. |

## 평가 절차 자체의 한계

이 점검은 지침·예제·양식이 중요한 구분을 표현할 수 있는지 확인한다. 다른 에이전트가 같은 요청에서 일관되게 행동하는지, 실제 인터뷰가 의도를 잘 발견하는지는 아직 알 수 없다.

## 다음 실제 검증의 입력과 판정

대상 프로젝트에서 원래 요청·현재 자료·작업 범위만 제공하고 스킬을 사용하게 한다. 결과를 미리 알려 주지 않은 검토자가 다음을 확인하면 자체 작성 편향을 줄일 수 있다. 진행 가능한 검토 수단과 사용자의 허용 범위에 맞춰 실행한다.

- 사용자 발언·관찰·에이전트 가정의 구분과 중요한 의도 누락.
- 핵심 과업의 시작·완료·예외를 화면·가이드·규칙으로 일관되게 설명하는가.
- 접근성 예외를 잘못 적용하거나 미확인을 통과로 바꾸는가.
- 실제 세션 없이 관찰·성공률을 만들어 내는가.
- 실제 사용자 테스트에서 유도·도움·환경 한계를 기록하는가.

실패가 확인되면 해당 사례·잘못된 결정·기대 행동·수정 버전을 남긴다. 스킬의 문장이나 제목을 그대로 검사하는 것을 행동 검증으로 삼지 않는다.
